# 原 540 维 u10000 的冻结 FP64 检查

四个归档细步锚点分别为前拉 588、594 和背推 587、594 帧。每个锚点使用原归档的首拍 decoder 输出、三个方向、10 帧历史、上拍动作和 42 个传感时刻的噪声。网络及其参数与缓冲、表示常量、FK 查表、参考张量、状态与输入均升至 FP64，离散索引保留原类型。全部模型冻结，沿原 H32 时钟运行，初始扰动后由该条预测轨迹自己的后继决定余下 31 拍的策略查询。

实际完成 **264 条有符号扰动、4 次预热、8 次基线、12 次方向 JVP、4 次 J32 反向梯度**。新增物理与优化均为 0。每个方向的 11 个幅度及其正负号合为 22 个独立 batch lane，基线与导数各用一个 lane。原始文件逐拍保存 145 列，含操作前的生存权重、操作后的存活概率、八项加权累计奖励、原目标、末端 Critic、端点／同步误差、全部 7+75 状态及 23 维 raw／clipped 动作。

**12/12 个方向在至少三个连续尺度上，J32 中心差分与反向梯度投影的绝对差持续缩小。** 在最细幅度 0.00001953125 上，12/12 同号，相对误差介于 0.00000685% 和 0.2393%。最大相对误差来自背推 594 的原 objective 方向，反向梯度投影为 0.0037085235，最细中心斜率为 0.0036996505。该方向在若干较粗尺度反号。原函数值的八项重构最大残差为 1.33e-15，J32 分解残差为 8.88e-16。重复基线逐拍一致。4 个方向在最细尺度前出现误差局部最小值，尾部波动与舍入相容。其余 8 个仍在向反向投影靠拢，给定尺度内的舍入平台 unresolved。

**这 12 次原生 forward-mode JVP 存在诊断实现问题。** 5 个 J32 方向与反向投影异号。第一步的动作切向量符合差分，而首个预测后继的根平移切向量已经被清零。对固定 TorchScript 函数 quat_apply，单位四元数旋转向量应保留输入切向量，实际返回 tangent=None。使用相同输入，反向 VJP 和 reverse-over-reverse JVP 都保留了该向量。诊断脚本已将默认 JVP 入口改为 reverse-over-reverse，保留原 native-dual 路径以解释实测。模型调用定额已经用完，修正入口只完成该算子反例验证。**整条 H32 的修正后 JVP、H1/H7 及八个分项的导数一致性保留 unresolved**。可使用已存轨迹逐拍重新计算差分，无需追加物理或模型推演。

原训练使用反向 AD。本次发现不足以判定训练核心违约，RefXY2 配对无需因此封存。这里的结论仅涉及原 u10000 四个锚点、冻结 FP64 的数学函数。历史 FP32 对照使用的 JVP 实现与本次原生 forward-mode 路径不同。
