## 1. 本阶段要达到的具体目标

在现有 `rail_bridge_front60_v2` 整机和单扇被动门上，继承官方 SuperMimic 的实际交互、世界模型监督、短时可微 rollout 和 Actor/Critic 更新流程，训练**由学习策略输出全身动作**的参考条件控制器。

按难度逐级达到：

1. 自由底盘＋轮腿＋机械臂＋夹爪的无门接触参考跟踪。
2. 抓持建立、小角度推拉、保持和释放的接触片段。
3. 从规定完整初态出发的连续单门前拉 60°，随后背推 25°；包含驶近、停稳、伸臂、抓持、开门、释放、退臂保持、收臂、倒车和终点停车。
4. 冻结基线，给出多训练 seed、开发/回归条件和新测试条件下的物理结果、模型误差与失败原因。

本阶段的“原样”指保留官方**学习机制与主要网络组织**，机器人资产、状态维度、混合动作、参考运动、门状态、奖励尺度、终止条件和环境封装做必要适配。不是把 G1 的 XML 换掉就能运行，也不是将 G1 权重直接装到 M1。

最终研究目标继续包含腕部 RGB-D、语言、本体历史、VLA、世界模型与可微动力学联合，以及实机验证。B0 先建立可复用的学习基线，不要求视觉/语言编码器已经训练好。

## 3. 先固定的算法与实现决定

### 3.1 默认路线

**在固定的 mjlab_research 中新增目标整机环境，调用固定官方 learners；原 native MuJoCo 工程保留为物理与任务基准。** MuJoCo/Warp 训练属于同一 MuJoCo 物理体系，不引入 UE/GENISOM。先适配官方环境封装，不并行开发另一套自写 runner。

如果确实遇到阻塞目标模型的后端不支持项，先保存具体模型元素、错误和物理对照，修最小必要适配。只有明确无法保留时，才评估 native 采集器＋官方 learner 的单一路线，并写出接口差异；不靠删碰撞、固定根或取消夹爪约束解决兼容性。

现有 `.venv` 保持不变，B0 使用独立 `.venv-b0` 或等效独立工作环境；第三方源码和环境可按固定来源重建，不提交大依赖目录。RTX Pro 6000 96 GB 可充分使用，不因算力预算缩减研究目标。

### 3.2 O1 配方与目标平台适配分开记录

O1 配方来源为 GenCoord、proprio/history10、motion slot=1、velocity slot=0、latent32、官方 normalizer/replay/return sampler；WM 主网络 `[2048,2048,2048]`，Actor `[2048,1024,512,256]`，Critic `[256,128]`，学习率 2e-4，WM 10×2048、8 状态窗口，Actor batch4096/H32，replay_ratio16，collection noise0.1，原 Muon/Adam 参数分组。以上是原始来源说明；已通过的目标平台实际配方见 `config/b0/free_servo_cloud.yaml`，当前为 128 worlds 等实际批量与平台动作尺度。现有接触/全程实际配置已在 config/b0/ 和各 run/actual_config.json 登记；当前按接续计划选择最小适配，不恢复旧的 4096 环境等数值来追求字面一致。

O6/O7 的全 Adam、cosine 和删采集噪声属于另外的实验配方。B0 初始不混用；如出现针对性证据，再建立命名变体。

以下必须适配并写入变更表：机器人/门状态、混合执行器、动作量纲、运动参考、轮/夹爪 FK、门动态、观测噪声、奖励与损失物理尺度、训练初始化及终止。保留主要网络形式不等于所有维度和数值一律照搬人形机器人；尤其不能把原角度/角速度噪声数值直接用于米制夹爪。真实采集和模型内合成观测采用一致的分块噪声约定。

### 3.3 当前上游变化的处理

[`5fb9229`](https://github.com/HybridRobotics/supermimic/commit/5fb92297ab4fe3d86629d9f0c635334791bb0d5f) 将身体速度目标按根偏航差旋转为 heading-relative 评分，并关联 mjlab 对应修改。O1 固定的两侧实现原本都按世界系身体速度评分，在该语义上一致。

登记 `candidate/not_applied`，不据此否定旧 O1 分数，也不只改 WM 奖励而留下旧仿真奖励。以后采用时两侧一起改、另记版本。

固定旧 pin 后按旧接口实现：`WorldModelEnv` 是抽象类，实际 `MultiTaskWorldModelEnv`；`step` 返回四项；`policy.update()` 内部采起点。不要从新 main 拷贝三项返回或 `update(starts)` 调用来拼接。

## 7. B0-03：无门接触的学习闭环

### 执行内容

1. 目标网络从零初始化；沿用官方网络形式、归一化、优化器分组和采样机制，记录必要的维度变化。

3. 运行官方 Actor/Critic 更新：一次策略更新内部固定 WM 参数，但保留动作→预测状态→奖励/价值的梯度。不能把 WM rollout 放进 `no_grad()`。
4. 真实交互与两类更新交替进行，记录采集步数、joint update 数、数据覆盖、损失、梯度、真实回报和任务错误。

6. 首次正式运行按 actor update=0/1000/5000/10000 保存诊断节点，之后每 10000 更新作固定开发评测；节点可依据实际迭代计数语义在启动前修正，不能用墙钟强制杀进程。完成关键能力后进入下一步，无需凑更新次数。

### 初版通过目标

先用 seed0 验证三个参考类型均能完整闭环；每个类型冻结 20 个有效小扰动条件，目标至少 18/20 完成。无接触跟踪的初版精度目标为：根位置 RMSE≤5 cm、根姿态 RMSE≤5°、TCP 位置 RMSE≤3 cm、有限角度关节按关节范围归一化后的 RMSE≤5%；轮速和夹爪宽度单独按各自单位报告。

这些是**本项目为首轮设置的暂定工程门槛**，不是论文在本平台上的结论。接触不能使用 3 cm TCP 误差当作抓持成功；B0-04/05 使用实际接触与更严格物理判据。若需变更门槛，先写明物理理由和版本，保留旧条件结果，不看完结果后静默降低标准。

### 输出与失败出口

`reports/B0_FREE_MOTION.md`、每类完整视频与逐案指标、真实/预测时序、参数更新和数据来源记录。若计算图通但真实任务未改善，优先区分动作语义、模型误差、价值/终止和优化问题；不立刻加入 VLA/MPC 或重写整个算法。

## 8. B0-04：动态门与接触片段

### 执行内容

1. 在相同 GenCoord 机制下增加门角/门速预测和机器人—门相对几何。同步更新 replay、编码/积分、loss、reset、reward/critic 所需状态，不使用真实未来门角补 WM。
2. 以同一次完整教师任务中的状态构造五类片段：接近并闭爪、稳定抓持、前拉约 5°/15°、背推约 5°/15°、松爪退臂并保持。每个片段明确起止事件和参考来源。
3. 片段 RSI 同时恢复机器人、门、速度、上一动作与需要的历史。新建 MjData 后接触缓存不可直接假定恢复，必要的接触重建过程单独标记。
4. 报告首次接触、稳定抓持、滑动/丢失、松爪等区域的模型误差。重点检查臂运动引起基座偏移、轮滑、夹爪与门动力学的联合预测。
5. 默认 Actor 继续 proprio＋reference；门真值供 WM/Critic 训练与评测。若观察缺失造成失败，单独做 privileged-object 诊断以判断问题，不替换原结果后宣称无特权通过。
6. 先保留 motion tracking 主奖励及必要的单位/几何适配。若需要额外门角进展/接触奖励，建立 `task_reward` 变体，真实环境和 WM 同步修改并保持相同奖励时序与 dt 缩放，保留纯 tracking 结果。新增项改变单步奖励范围时，同步核对 `WorldModelEnv.max_step_reward` 和 `ActorCriticPolicyLearner._v_max`，防止价值/回报被旧上界错误截断。

### 通过目标

每类片段先完成 nominal；再用冻结的 20 个有效小扰动初态，目标至少 18/20。保持/推拉片段必须达到目标门角、满足抓持和身体条件；释放片段要真实脱离并完成要求的保持。评价使用现有接触/失抓阈值，而非只看 reward。

中途初始化片段即使全部通过，也只说明局部接触能力，不构成 B0-05 全程任务通过。若失败，按具体事件回到数据覆盖、动态状态遗漏、模型预测或策略优化排查。

### 输出

`reports/B0_CONTACT_SEGMENTS.md`、每类完整片段、预测对照、门动态扩展说明与适配差异表。

## 9. B0-05：统一初态的连续单门任务

### 执行内容

1. 先前拉：由冻结的整条参考和策略从 0.30 m 外驶近的任务初态运行到倒车后稳定结束。
2. 前拉成立后用相同接口训练背推 25°。两侧的站位和参考不同，模型/动作/事件评估体系一致。
3. 形成同时含两侧参考的训练库，验证一个统一 WM/Actor 是否维持两侧能力。记录单任务到共同训练时是否遗忘，不用两个最佳单侧检查点拼成统一成绩。
4. 训练允许片段采样和 RSI，评测全程不允许 reset、教师接管、门角直接写入、门电机或把手焊接。固定低层伺服可以保留，P6 状态机不能输出策略动作。
5. 事件评估器只观察并判定阶段，不产生导航、IK 或开门命令。参考时间条件可以驱动 Actor，但必须说明是 reference-conditioned tracking；不能称语言指令自主规划。

### 完整任务判据

原 P6 配置按 `p4_pull_60.yaml/p4_push.yaml → p5.yaml → p6_pull.yaml → 推门时再 p6_push.yaml` 合并，不存在 `p6.yaml`。

| 判据 | B0 完整任务继承要求 |
| --- | --- |
| 门角 | 前拉目标 60°，背推 25°，终态及规定保持阶段误差≤2° |
| 驶近与停车 | 按原操作区/航向、速度与轮载条件确认；不是脚本时间到就算到位 |
| 抓持 | 两指真实接触与几何/开口条件，确认 0.20 s；失抓持续 0.15 s 等失败条件沿用 |
| 释放后 | 松爪、退臂后独立连续保持 3 s，门保持目标，机器人不再接触门 |
| 终点 | 收臂、倒车后再独立连续保持 3 s；水平速度<0.005 m/s、偏航速率绝对值<0.5°/s |
| 物理约束 | 每个 2 ms 步检查非预期接触、失稳、限位、持续饱和/轮滑等；六臂关节有符号限位余量不能为负 |
| 时间与完整性 | 保留原阶段物理超时与事件顺序；缺少必需事件、用户中断、异常退出均单独记结果，不能计为完成 |

具体边界以冻结配置和评估代码为准。不要把较松的 tracking soft termination 代替任务硬失败判定；两者可以并存。原 `grip_net_force_limit_n=6` 是名义仿真诊断阈值，不声称是实机额定安全载荷。

先每侧完成一条 nominal，再在既有 C01–C20 回归清单评估。初版目标每侧至少 18/20；任何失败都保留。B0 不要求胜过已有教师的 20/20，首先证明在相同物理要求下由学习策略完成。

### 输出

`reports/B0_FULL_TASK.md`、两侧完整视频、逐案结果与失败事件、与 P6 同判据对比、选用检查点和参考选择规则。明确每条动作来自哪个策略，不能只提交剪辑。

## 10. B0-06：冻结与测试

### 评测协议

以下样本数与门槛为本次规划设置的工程目标，执行前写入配置；不是已经测得的结果。

| 集合 | 定义 | 目标与报告方式 |
| --- | --- | --- |
| nominal | 两侧各一个固定完整初态 | 先完成完整闭环；重复同一确定性初态只记复跑一致性 |
| 开发/回归 | 每侧 C01–C20，条件身份固定 | 每训练 seed、每侧≥18/20；已用于开发，不能称未见泛化 |
| held-out | 每侧新增 50 个有效条件，固定清单后保留到冻结评测 | 每训练 seed、每侧≥40/50；报告全部失败与条件范围 |
| 训练随机性 | 默认 seed0/1/2 三个独立目标训练 | 每个 seed 独立报告；不能跨侧/跨 seed 平均掩盖某个模型失效 |

held-out 的初版范围沿用已知可行邻域：世界初始 XY 各±5 cm、yaw±5°、门初角 0–5°、轮/指摩擦倍率 0.8–1.2、铰链摩擦/阻尼倍率 0.5–1.5。均围绕当前前拉/95°背推名义站位生成，与原离散 C01–C20 去重。先独立检查初态穿透/几何有效性，按固定 seed 生成并保存完整数值；无效初态的排除规则在评测前固定。

条件是物理任务范围，不要求训练必须完全不见每个单变量范围；主要检验未用于参数选择的具体组合。训练随机化范围、参考是否见过及初始对齐规则均写明。不得现场为每个测试条件重跑教师生成最优参考。

初版可在同一预注册清单上评估训练后端与原 native MuJoCo 后端，至少两侧 nominal 都要跨后端跑通；完整回归成绩分后端列出。训练后端通过而 native 失败属于后端迁移限制，不能混为同一成绩。若接触数值差异导致统计变化，保存模型和物理参数差异，勿以轨迹不逐位相同判定必然错误。

### 冻结输出

- `reports/B0_BASELINE_REPORT.md`：任务、状态/动作、官方保留与适配、数据覆盖、训练计数、完整任务结果、局限。
- `results/b0/<run_id>/`：实际配置、逐案 JSON/CSV、模型误差、曲线、完整代表性视频与所有失败索引。
- 权重位置、normalizer 和来源版本；保存范围是否支持完整 resume。
- 更新 `PROJECT_STATE.md` 与 `prompts/NEXT_RUN.txt`，指出后续 R1/R4 需要解决的具体问题。

**允许两类诚实的阶段结论：**达到目标则冻结成功基线；若经过针对性排查仍无法达到，则冻结“已通过步骤＋真实失败＋限制判断＋下一项适配”。后者不是 B0 全部通过，但可以作为后续模型/方法适配的证据，避免为等到一个完美基线无限重复同类训练。

## 11. 变更与失败处理

| 观察到的问题 | 首先核查 | 本阶段允许的处理 |
| --- | --- | --- |
| 教师在训练后端也失败 | 物理参数、执行器语义、坐标、门/碰撞、初始化 | 修环境/映射；保留两侧真实结果 |
| WM loss 很小但 rollout 偏离 | 时间错位、跨 reset、归一化、动作重复缩放、数据覆盖 | 修真实数据或表示，不用预测数据覆盖真值 |
| 无接触通过、抓门失败 | 门动态/相对几何、夹爪单位、接触模式覆盖、奖励尺度 | 最小对象适配，补采具体失败附近数据 |
| WM 预测可用但策略无改善 | BPTT 是否断开、value/termination、reward一致性、优化器配置 | 针对性训练诊断或命名超参变体 |
| 片段成功、全程失败 | 初始化依赖、参考时钟、阶段累积误差、数据分布、状态机暗中接管 | 补全程训练/评测，保留真实失败，不拼片段 |
| 训练后端通过、native失败 | 动力学版本、求解器/接触、执行器映射 | 单独处理后端迁移，不改原结果口径 |
| 需要新状态估计/模型结构 | 已确认的不可观测性或模型局限 | 输出限制基线，交给 R1/R4；不继续宣称纯官方迁移 |

每个命名训练试验在启动前写明假设、初始 collection/joint update、评估节点和本区块的终点。默认以新增 50000 次 Actor update 为一个诊断区块，按前文节点评测；它是保存/诊断节点，不是后台墙钟终止或整个 B0 的总预算。实际计数若与所选 runner 不同，先映射并记录再运行。

能力仍在改善时可自主续接下一区块并记录理由；已达本步骤目标则推进下一步骤。连续两个完整区块在同一冻结开发集上成功案例没有增加、主要失败类型也没有改善时，先进行一次针对该失败的诊断，提出可检验的改动或数据补采。没有新的证据/处理项时冻结限制报告，不以相同配置无限重启。任何变体先记录改变和判断依据，不强行凑满算力或按墙钟杀任务。

本阶段只做能消除具体风险的检查，不建立通用防御框架、哈希套件、mock/冒烟测试堆叠。模型预测、梯度路径和物理闭环检查属于研究本身，需要真实证据。
