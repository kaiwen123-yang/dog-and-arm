## 1. 本期要得到什么

## 3. 导出的对象是完整推理链

源代码 `learning/b0/contact_policy.py` 中 `build_actor`、`load_policy`、`ReferenceResidualActor.raw`、`StanceArmActor.raw`、`DoorMotions.goals` 表明：网络消费 **10×77 的全机本体/历史、546 维 goal，输出 23 路动作**。原 540 维 goal 后的六维，是参考 TCP Jacobian 对参考根位置减当前根位置的映射结果。[策略代码](../learning/b0/contact_policy.py) · [解析映射](../learning/b0/stance_arm.py)

导出包至少带上：Actor 权重与冻结归一化统计、解析配置、关节名称/顺序/零位/单位、动作 offset/scale 和裁剪顺序、参考数据及身份、参考钟及末帧规则、十帧历史与上一动作更新规则、参考前馈和解析修正、可复现推理入口。训练用 WM、Critic、优化器和 replay 保留为来源资产，第一期在线推理无需加载它们。

首先保留完整网络和输入语义，在输出映射完成后只向实机发送六臂目标及夹口目标。**截取输出不等于把网络改造成七通道策略；历史里未执行的腿轮动作必须有明确的固定/屏蔽规则。**

| 接口 | 已核实源语义 | 桌面处理 |
| --- | --- | --- |
| 0–11 / 12–15 | 腿关节位置 / 轮角速度 | 实机不发送；固定上下文及历史如实登记 |
| 16–21 | J1–J6 目标角，rad | 按名称映射实际方向、零位、限位，不假定数组索引相同 |
| 22 | 夹口全宽，m | SDK 接收全宽；毫米只在展示层换算 |
| raw → clipped | 合成参考、残差和解析项后裁剪至原区间 | 保留顺序，记录任何新增适配限幅 |
| 物理目标 | `offset + scale * clipped` | 导出六臂角和全夹口宽，不把 raw 当 rad |
| 仿真单指驱动 | 全宽再乘 0.5 | 仅属于两指仿真映射，SDK 不再乘 0.5 |
| 仿真 servo | 原 2 ms 更新及 `qfrc_bias/gain` | 不是 SDK `move_j` 的等价指令，不能机械叠加补偿 |
| 策略时钟 | 20 ms，目标 50 Hz | 测端到端延迟与反馈年龄；约 200 Hz 状态接收不证明 50 Hz 闭环已成立 |

来源：[ActionMap 与 NativePlant](../learning/b0/physics.py)、[模型/effort 坐标](../learning/b0/model.py)、[H0 实测](../reports/H0_HARDWARE_REPORT.md)。官方 SDK 的关节命令/反馈使用 rad，固件和控制模式行为需匹配现场安装版本；本期沿用已验环境，不根据最新网页默认升级。[官方驱动说明](https://github.com/agilexrobotics/pyAgxArm/blob/master/pyAgxArm/protocols/can_protocol/drivers/piper/default/driver.py) · [官方固件路由](https://github.com/agilexrobotics/pyAgxArm/blob/master/docs/piper/firmware_reference.md)

先用现有 PyTorch 推理形式完成可复现导出与主机计时。只有目标主机的兼容性或实测性能需要时才增加 ONNX 等导出；届时重新核对同输入的输出与闭环结果。

## 4. 固定桌面适配必须解决的四件事

### 4.1 使用现场几何建立独立物理模型

复用官方 Piper H、双指耦合、腕部相机外形及被动门资产，建立真实的固定安装臂、桌面、门框、门轴和把手。记录 Piper base 到门轴/把手的变换、夹持尺寸、开门方向、目标角、门的阻力与是否存在锁舌/闭门器。首版优先匹配已有无锁舌、无闭门器被动门任务；实际治具不同就显式记录，不能默认为同一任务。

旧 P4 固定的是整个 M1 根，仍保留腿轮，并不是现成的裸 Piper 桌面模型；其前拉单案严格 60°字段也未通过。仅继承其几何和失败经验。[P4 限制](../reports/P4_FIXED_BASE_CONTACT.md) · [Piper 资产生成](../scripts/model_parts/piper.py)

先检查整个开门圆弧、释放、撤臂和收臂都可达，不能只检查初始把手。实际门角、把手到铰链半径和治具位置先登记再试验；60°前拉/25°背推是旧场景参照，不保证新桌面布局可达。需要改门位或参考时，按桌面任务记录改动，不缩放机器人或伪改关节范围。

### 4.2 把固定底座映射到原策略坐标

若保留原网络，建立“真实固定 Piper base ↔ 原模型安装变换下的虚拟 M1 root”映射。这个虚拟根和固定腿轮上下文只是兼容表示，不能描述为不存在的 M1 传感器反馈。根速度为零、重力方向和固定姿态从安装定义获得，腿轮状态采用明示的固定值，不一律补零。

参考重定位后重新计算同坐标系的 FK/Jacobian，验证六维解析修正是否仍有效。若参考根和固定根重合导致修正自然为零，记录其数学依据；不得直接删掉输入掩盖依赖。真实臂角、夹口、因果速度估计、反馈时间和上一条实际执行命令持续进入历史。初始历史按源接口的 reset/无上一动作语义用真实初态填充，再逐拍替换为实际反馈；填充项明确属于初始化，不从旧整机轨迹伪造一段已经发生的执行历史。对未执行的腿轮通道使用适配器定义的固定命令，不能把原网络未执行输出伪装为执行历史。

### 4.3 重建桌面参考与连续起点

提取/重定向原抓持、开门、保持、释放、撤臂和收臂参考，去掉驶近、停车、底盘退出的任务阶段。实际起点为登记的无接触准备姿态，参考和历史从该任务初始化；接触后依靠真实物理后继重新查询 Actor。若采用新的参考路径、速度或阶段调度，明确列为适配变化。

低速试验同时对齐参考进度和控制时钟，不能只减慢 SDK 速度而让原参考钟继续跑。原 20 ms 推理周期与重定时的参考进度分开记录。只有分段测试通过后再从同一个初态连续执行，不能拼接片段称完整成功。

### 4.4 先判断导出、几何与伺服，再决定是否训练

导出前后先在原成功轨迹代表状态上核对 goal/history、raw23、clipped23、七路物理命令与参考帧。随后在新桌面模型中运行完整闭环。数值等价证明导出正确，桌面成功才证明固定安装适配可用。

若失败，依次区分：接口错误、整条路径不可达、实际 servo 响应不同、固定上下文引起的策略分布变化。前三类先做对应工程修正；确认是策略能力缺口时，在同一集中执行轮使用桌面示教/仿真数据做有界的残差适配或七动作蒸馏。原 u1 冻结对照保留，适配数据与实际更新数单列。**不恢复整套 B0 标准迁移，也不把换成 IK 控制器的成功记为导出策略成功。**

本次计划发布实际优化为 0。后续需要训练时，执行平台先按数据量和实测吞吐把本轮配方、初态、检查点和计算预算写入运行登记再执行，不继承旧 +500/+1000/u15000 余额，不承诺某个更新数必然成功。停止/延长看完整桌面任务与真实跟踪问题，不再增设一套 WM 误差放行轮。

## 5. 一个集中执行轮的顺序

| 工作包 | 实际工作 | 本包可查看结果 |
| --- | --- | --- |
| A：恢复与导出 | 找到源 u1 和完整参考；导出完整推理包；代表输入核对；目标主机计时 | 导出清单、数值对照、延迟分位数、可运行推理入口 |
| B：固定桌面闭环 | 构建独立固定 Piper 场景；重定位参考；完整推/拉可达性与 Actor 闭环；必要的定向适配 | 配置、逐案结果、清晰的连续桌面仿真视频 |
| C：真实接口对齐 | 复用原 SDK；先只读 shadow，再现场空载目标响应；记录单位、模式、时钟、跟踪与停止 | 真反馈与预测命令对照、实际发送/反馈延迟、跟踪曲线 |
| D：真实整段任务 | 低速抓持及短程开门后，在同一配置连续完成开门、释放与收臂；立即保存首个完整视频 | 同回合视频、原始时间/命令/状态、实际完成事件与失败记录 |
| E：收束并交接 | 首次成功后追加两次同配置名义重复，报告所有尝试；可达时补另一方向 | `成功数/总尝试数`、适用范围、冻结部署包、第二期数据入口 |

A/B 可与只读现场信息整理、SDK 封装并行，C/D 按物理依赖顺序推进；不在每个小文件完成后结束一轮。已有硬件可用时一直推进到完整任务，不只交付“导出成功”。远端没有真实机器人时，完成全部可做的恢复、导出、仿真和部署准备，并给出唯一缺少的现场输入/操作；如实标记 D 尚未执行。

首个成功就交视频，追加两次重复用于说明复现性，不把它扩成旧 D/C/seed/H 长期资格。一次成功证明该条件下的能力，不能由 1/3 宣称稳定 100%；若重复失败，保存原因和限定结论。本支线按实际完整能力及部署/数据交付收束，不控制多模态主线是否启动；未完成的另一方向和鲁棒性测试明确排入后续，不能静默宣称双侧已过。

## 6. 真实硬件的执行范围

复用 `/home/kaiwen/research/OSCBF-research` 的 `PiperDevice`、已验证 pyAgxArm 环境和本仓库 H0 记录器。历史版本为 pyAgxArm 1.0.0/PIPER_H/V189，现场先核对当前版本、关节状态与装配，不重装 SDK、刷固件、自动回零或直接重放旧绝对姿态。[H0 配置](../config/hardware_session.yaml) · [既有现场动作入口](../scripts/h0_operator_motion.py)

部署入口默认只读/不发运动命令，现场运行时通过明确的 `--execute` 入口启动。一个进程拥有运动发送权，图像录制与推理解耦；验证新鲜反馈、命令间隔以及中止/断流后的既有停止方式，再进入接触。H0 只完成小幅运动和正常停止，并没有验证本期的策略闭环与断流停止。具体速度、关节/夹口限位和异常停止值取现场配置及当前测量，不在计划里编造一套通用数值。

相机先作为同步记录设备；已知固定门位可以由测量登记，不为第一期额外强制训练视觉定位。若实际用图像定位把手，才需要匹配当前安装的手眼与几何参数。优先核对已有标定能否复用；本仓库 H0 尚未证明手眼完成，也记录了 RGB 畸变参数差异。不同工程的标定不能直接认作当前有效。现有附件载荷按能读取的配置记录，必要的实测为仿真实机差异服务，不把采购标定板当作恢复/导出的启动条件。

实机的夹爪设定力、电机电流/估计力矩与门上合力是不同量。没有校准测量依据就把真实门力写 `NA`，不把仿真 6 N 线或 SDK 的 1 N 命令当作实机已测门力。门保持和释放后的可接受运动按实际被动门定义；本期不自动扩大为解锁或闭门器任务。

## 7. 结果与比例比较

评测从登记准备姿态开始，到安全收臂停稳结束；用同一回合的命令、反馈和画面核对所有事件。运行日志与观测证据共同判断实际抓持、开门和释放；仅执行完 reference clock 不算成功。

| 量 | 记录与比较 |
| --- | --- |
| 完整任务 | 每方向成功数/全部尝试数；第一次失败阶段；人为接管和中止单列 |
| 门角 | 实际角度、目标角度、测量来源/分辨率；`实际角度/登记目标角度` |
| 几何规模 | 把手至铰链半径、门位、夹持宽度、完整圆弧可达性；必要时用把手行程 `r×θ`（θ为rad）比较 |
| 关节跟踪 | 每轴 rad/deg 误差、P95、最大值，以及 `RMSE/(该轴实际允许范围)` |
| 夹口 | 全宽 mm、目标/反馈、夹持物尺寸和释放裕量；两指模型与实机反馈来源分开 |
| 时间 | 各事件耗时、整段耗时、`实机耗时/同一桌面参考仿真耗时`，相同 phase-rate 条件下比较 |
| 延迟 | 推理、发送、反馈年龄、命令周期的 P50/P95/P99/最大值和失约次数，注明采样长度 |
| 力/电流 | 仿真接触力和真实传感量分别报告；不可测门力保持 NA |

任务几何、目标角和容差在正式尝试前锁定，来源为实际治具与测量精度。原整机 3 mm/75拍判据和论文 0.90/0.88 不直接搬来给新桌面任务“算达标率”。同时报告绝对数值和比例，避免分母改变掩盖退化。
