## 3. B0 结束后具体继承什么

1. **继承物理环境**：同一机器人、执行器、被动门、接触几何、动作单位和成功判据。加入视觉时不顺手改变控制频率与开门目标。
2. **继承学习闭环**：真实物理交互 → replay → WM 监督 → 固定 WM 参数的短时策略优化 → 再交互。R5 不从零重建这条链路。
3. **继承数据与结果**：参考库、当前策略交互数据、完整初态评测、困难片段和所有版本说明。
4. **替换可观测信息来源**：B0 的参考/特权诊断与未来视觉语言控制分别标明，逐项用腕部视觉、本体历史和状态估计代替部署时不可得的量。
5. **保留比较基准**：冻结 P6 教师、B0 官方机制迁移、后续多模态模型均在相同任务判据上报告。

R1 的相机扩展不要求 B0 先做大规模图像训练。相机几何保留，能同步记录就记录；没有记录的历史图像不事后伪造。最终保留 RGB 与深度的融合目标，不能因初期采用 RGB 编码器而悄悄删掉深度路线。

## 4. 世界模型、可微动力学与 VLA 如何结合

后续主干的待验证定义是：多模态历史先形成当前状态/信念，VLA 根据指令与该状态产生动作或动作条件；世界模型在同一动作语义下预测全身和物体的演化，为训练提供短时回报、失败概率与梯度。实测/仿真交互不断修正模型。

| 模块 | 需要建模的内容 | 应避免的混淆 |
| --- | --- | --- |
| 多模态状态估计 | 腕部图像/深度、本体、相机运动与历史推断的对象相对状态 | 看不见的门侧/接触状态不能直接读仿真真值后称为视觉能力 |
| 可微动力学 | 全身惯性耦合、轮地作用、臂运动引起的基座响应、夹持与被动门运动 | 可微近似的导数不自动等于接触物理的精确导数 |
| 世界模型其他部分 | 隐状态、对象/接触、任务进展、可选观测预测与不确定性 | 预测视频更好不自动证明动作决策更好 |
| VLA | 语言条件与多模态观测到动作/技能/参考的映射 | 官方未来参考帧不是 VLA 动作块；动作块长度与执行步数后续比较 |
| SuperMimic 式优化 | 用学习到的可微模型展开短时未来，以回报梯度更新策略 | 不对 MuJoCo 求导；不能在模型 rollout 中读取真实未来状态或图像 |

R3/R4 先分别建立可用基线，R5 再比较：冻结部分模块、交替更新、逐步扩大联合梯度范围。闭环收益须同时与观测、动作和评测条件匹配的基线比较；B0 保留作能力与信息条件参照。没有证据前不预设所有参数必须从第一轮同时端到端更新，也不把纯模仿结果写成模型式优化已经产生收益。

## 5. RoboMIND 的处理规则

RoboMIND 是 R2/R3 的**可选数据支线**，不进入 B0 的前置依赖。主线数据来自本平台的仿真，后续加入实测数据。数据集版本、授权、模态、视角、语言、时间戳和动作单位须按下载到的实际子集核对。

处理次序：

1. 只选可能支持腕部观察、抓持/推拉语义或视觉表征的子集，建立字段与本任务的对应表。
2. 明确跨机器人差异。缺少轮腿动作、全身姿态、门状态或接触标签的字段保持缺失与 mask，不能补零充当监督；不能直接作为完整腿臂动力学数据。
3. 在本平台仿真中设置同一自采数据、同一训练/评测划分的“使用/不使用外部数据”比较，主要看任务成功、数据效率及非预期接触。
4. 先用开发/验证集选择；最终冻结测试集只作报告。若不同训练 seed 下没有可重复收益，或负迁移导致任务能力下降，取消该支线并记录原因，不为已经下载数据继续投入。

不以公共数据替代手眼、时延和真实动力学适配；是否减少实机示教量，须由 R7 的实际学习曲线决定。参考入口：[RoboMIND 官方项目](https://x-humanoid-robomind.github.io/)、[官方数据说明](https://huggingface.co/datasets/x-humanoid-robomind/RoboMIND)、[官方数据工具](https://github.com/Open-X-Humanoid/RoboMIND-dataset-utils)。官方说明已列出多个版本与对应数据处理注意事项，实际采用时再次核对具体版本和子集。
