## 3. 当前缺口已经从笼统的“继续训练”缩小到具体链路

### 数据贯通

新 `lanes_modes_v1` 进入了预热，却没有进入后续联训离线 WM 池。在线 open/hold 仅 1,087/219,677＝0.4948%，且全部是 terminal 区间。固定握持集的 H32 P95 在联训 u10 已变为 127.19/149.47 mm。需要让必要真实数据持续参与原 H1/H7，并检查实际 minibatch，而不是只再预热后继续长训。[配置与代码审查](../reports/B0_LANES_ROUND_REVIEW_20261124.md#2-新证据一预热数据没有全部留在联训中)

### 策略首动作与模型响应

旧 u50 两处诊断的满 20 ms 真实夹口约68.35/66.51mm，模型仍预测22–26mm；这是失败后积分的响应，不能当成正式2ms存续。下一轮要在训练身份上现场查询Actor，分组测臂/夹口组合。22.04/22.47mm是持续双指子集的条件最大命令，整个多模式训练数据已覆盖到100mm，不能直接推出动作全局越界。[响应证据](../results/b0/standard_lanes_20261124/entry_response_matched_u50.json) · [全局覆盖](../results/b0/standard_lanes_20261124/coverage.json)

### 原目标的学习方向

u200仅夹口首20ms动作率复算为−0.18767/−0.35863，正tracking总上界+0.1，说明原目标并非完全忽略这种突变。还需分解WM局部响应、实际Actor起点、未来tracking、生存权重和Critic如何共同影响更新。尚不能认定必须改奖励，更不能跳到新算法来掩盖迁移问题。[代数复算与限制](../results/b0/lanes_review_20261124/audit_summary.json)

这三项是下一轮可直接动手解决或验证的内容。它们有了具体代码/数据位置，不等于已经解决；仍要由真实持续接触和正式通过来证明收益。

## 4. 为什么不能计算“还差多少论文分数”

当前 u200 十片段 effort 均值为 0.18180，但它不是从完整初态连续完成前拉/背推的全长物理回报。因此不能写“距0.90还差0.7182”，也不能拿旧单片段0.97191代替完整成功。

0.90是论文SONIC参照线，0.88是本项目预登记绝对0.02容差，不是作者宣布的SuperMimic接近阈值。M1＋Piper门交互与原G1 benchmark不同。原论文WM状态误差0.007–0.011不能直接与TCP毫米误差相减。三次联训进程合计310.13秒没有包括全轮成本，也不等于论文独占GPU时间。[指标协议](B0_PAPER_BASELINE_PROTOCOL.md)

可靠的距离表述是：**标准采集与学习管线已形成，最早的接触能力门槛仍未通过；之后还有接触开发、连续双侧与跨后端、独立seed、冻结H和完整回报验证。完整分数差值目前NA。**
