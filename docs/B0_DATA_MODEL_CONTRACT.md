## 1. 三种数据不能混用

| 数据 | 来源与用途 | 必须保留 | 不能据此声称 |
| --- | --- | --- | --- |
| P6 工程结果 | 已验证脚本在真实物理仿真中的任务记录，作为教师和比较 | 原始版本、case、成功/失败/中断、完整时间段 | 学习策略已经完成任务 |
| 运动参考库 | 可执行的目标机器人参考，用于目标条件与跟踪奖励 | root、关节、速度、名称、采样间隔；有门时包含对应门参考及场景元信息 | 只有参考就已经有状态—动作—下一状态监督 |
| 交互 replay | 教师预采集或当前学习策略实际执行产生的 transition | 执行前状态、实际命令、下一状态、终止原因、上下文、来源 | 把参考帧相邻相减或想象 rollout 当成真实交互 |

现有 summary、25 Hz trace、视频、六轴限位余量表用途不同。先检查 `results/raw_large/p6/...` 的真实可用字段；这些大文件未必位于 GitHub。缺少完整动作、本体速度、根状态或采样频率不符时，在新的 B0 目录运行冻结教师并补采，不能用零值或猜测命令补齐。

只为 B0 补采必要参考与交互，不重新跑 P6 全清单来证明已经成立的 40 案结果，不覆盖旧原始数据。

## 2. 物理状态与坐标

基本单位：m、s、rad、N、N·m；四元数写明 `wxyz`。世界系 Z 向上，机器人本体系 X 前、Y 左、Z 上；相机光学系 X 右、Y 下、Z 前。每个速度字段必须注明表达坐标系，不能将 MuJoCo 原始自由根 `qvel` 直接假定为全部世界系速度。

| 状态块 | 必须包含 | 表示与注意事项 |
| --- | --- | --- |
| 自由基座 | 位置、姿态、线/角速度 | 原始世界量完整保存；网络可采用 GenCoord 去除水平绝对位置/偏航后的表示，辅助状态保存积分所需量 |
| 12 个腿关节 | 角度、角速度、限位 | 明确名称与顺序；不能仅保留底盘 vx/omega 而丢掉支撑状态 |
| 4 个轮关节 | 轮角、轮速 | 原始角度可连续展开；网络可用周期表示；不要把持续滚动当成超过普通旋转关节限位 |
| Piper 六轴 | 实际角度、角速度 | 保留逐物理步的有符号限位余量用于评测 |
| 夹爪 | 两指实际位移/速度、开口宽度与指间约束残差 | WM 初版保留两指实际状态，或等价的宽度＋约束残差及对应速度；动作仍只有一个。q1=w/2、q2=-w/2 首先是命令映射/理想约束，不能强制抹掉真实接触下的等式残差 |
| 被动门 | theta、theta_dot、门轴/把手几何、机器人相对门的位姿 | 动态门状态必须随每个预测步更新；不能放入 rollout 内恒定的 sim_ctx |
| 执行器记忆 | 上一动作；若有滤波、积分或延迟则包含对应状态 | B0 初版尽量用无额外记忆的固定伺服；确需记忆时必须加入模型状态，不能只给 actor history 后声称 WM 已知 |
| 接触监督与审计 | 指—目标杆、轮—地、非预期碰撞、力与滑动 | 初期可以只作监督/评测；若作为 WM 输入，必须定义想象阶段如何预测/更新，不能不断读取真实仿真标签 |

机器人原始组合模型是 `nq=31/nv=30/nu=23/neq=1`，加入一个门铰链后的编译维度应另行记录。只有实测证明夹爪等式残差可忽略，才可降为单宽度状态并记录该近似的误差；不能修改物理模型把第二个真实夹指删掉。

## 3. 动作的默认设计

默认策略每 20 ms 输出一个 23 维动作；物理步长沿用 2 ms，因此 decimation=10。该选择保持 O1 的 50 Hz 策略时间尺度，同时保留 P6 的物理时间步，是**目标平台的适配决定**。若实际接触精度要求变更频率，应同时更新采样、参考、积分与模型训练配置，另记版本。

| 逻辑块 | 维数 | 默认物理命令 |
| --- | ---: | --- |
| 腿 | 12 | 有限关节目标角，由固定伺服实现 |
| 轮 | 4 | 各轮目标角速度，保留轴向正负号 |
| 臂 | 6 | 六轴目标角，由固定伺服实现 |
| 夹爪 | 1 | 开口宽度 m，再转换为主动指目标位移 |

这只是逻辑分组，**实际 XML 顺序是交错的**。按关节和 actuator 名称构造双向索引；不能假定前 12 个通道全是腿。原组合 XML 的 motor 与 P6 派生场景的 position/velocity servo 也不是同一种 ctrl 语义；以实际构造的训练场景为准。

原始策略输出、裁剪后输出、缩放后物理目标、执行器 ctrl、实际执行力/矩分开记录：

`policy_raw -> policy_clipped -> physical_target -> actuator_ctrl -> actuator_force`。

WM 保存和接收的动作采用所选官方 `Dynamics` 约定的 **post-clamp policy output**，网络内只执行一次 scale/offset。action history、真实环境与模型内 rollout 使用相同语义。夹爪宽度到指位移的 1/2 系数不能应用两次；接触力与电机广义力分别记录。

固定伺服沿用已验证 P6 的合理增益/力矩限幅并记录实际值；P6 中的 `qfrc_bias` 补偿若保留，必须作为明确的执行器模型，在采集与训练环境中一致实现并说明使用的状态。禁止把 P6 的站位导航、航向积分器、IK、开门状态机包装成“低层伺服”继续替策略输出。目标平台训练不受当前实机 SDK 接口限制，真实执行映射留待 R7 实测适配。

官方 `extract_action_scale_offset` 只读取第一个 action term。B0 须显式聚合全通道映射或提供等价统一 action term，保证轮速、角度、夹爪单位均被正确处理。

## 4. Actor、WM 与 Critic 的信息边界

| 使用者 | B0 默认信息 | 不能静默加入 |
| --- | --- | --- |
| Actor | 官方 proprio 风格：重力方向/姿态相关量、角速度、关节/轮/夹爪状态、上一动作与 10 帧历史；目标机器人运动参考条件 | 门角、真实把手位姿、真实接触力、世界绝对根位置等额外特权量；加了就标成单独 privileged baseline |
| WM | 当前完整物理表示、动作、静态/逐回合参数上下文、必要执行器状态；B0-04 起包含门的动态状态与相对几何 | 用真实未来状态替换自己的预测；把变化的门角/接触藏入恒定 context |
| Critic | 官方方式的完整状态、目标及上下文，允许训练特权信息 | 把 Critic 的特权输入自动透传到 Actor |
| 最终多模态策略 | 语言、腕部 RGB-D、本体与历史/估计状态 | 部署时不可得的对象真值或未来传感器帧 |

保留官方观测噪声机制，但按腿/轮/臂的 rad、rad/s 和夹爪的 m、m/s 分块定义幅度。O1 对全部 joint_pos/joint_vel 使用的 0.01/0.5 不能直接搬到米制夹爪，否则变成 ±1 cm、±0.5 m/s。实际幅度在 B0-01 配置中冻结，真实采集与模型内合成观测一致，记录为平台适配。

10 帧 actor history 不等于 WM 有 10 帧历史；所选 O1 的基本 WM 是当前 rep_state/action/sim_ctx 到下一状态。历史是否足以消除接触/执行器的隐状态问题，要根据预测残差判断。

参考窗口是事先给定的**参考运动未来帧**。它不是实际未来观测，也不是 VLA 的动作块。B0 默认按固定策略步推进参考时间；不允许 P6 教师根据真实门角在线改参考或选择动作，除非单列为新方法适配并保留原基线。

## 5. GenCoord 与动态门扩展

先保留“预测速度变化 → 解析积分 → 可微 FK”的主要机制，适配自由基座、轮、六轴臂及滑动夹爪。不要直接套用 MaxCoord 中特定人形关节链的 IK。

- 记录所选实现的 `dt` 和 `decimation`。O1 是 5 ms×4；B0 默认为 2 ms×10。GenCoord 若使用 `c=(d+1)/(2d)`，B0 对应 0.55，不能照抄 O1 的 0.625。
- 轮自旋角/轮体朝向与机体/手部姿态的跟踪目标分开。若轮几何轴对称，避免对无任务意义的轮绝对相位施加强姿态奖励；先核对真实网格与碰撞形状，再决定掩码。
- 夹爪以米建模，不能使用“0.1 rad 关节误差”直接给 prismatic 宽度定损失。按状态块列出单位、归一化尺度和权重；先使用物理尺度，再用冻结开发数据核对。
- 门是独立世界实体，不是挂在机身上的一个臂关节。使用门角/速度与门轴相对根/手的几何描述；同一门角下机器人到门的距离和航向不同，转移也可能不同。
- 在预测的根/关节与预测门角上重算 TCP—把手关系；门轴世界位姿是静态场景参数，但其相对机器人坐标随根运动更新。
- 必须确认当前 research FK 对 slide joint 的支持；若缺失，补目标机器人的可微 FK 映射并做实际 FK 对照，不通过删夹爪或强套 hinge 掩盖差异。
- 门角的积分与机器人状态同一步推进，输出门运动误差；不能只预测机器人、再从真实仿真读取门的下一状态拼成完整 WM。

## 6. Episode 最小记录

每条 episode 至少包括以下分组。字段最终名称在首次实现的 schema 中固定；本文件规定语义。

| 分组 | 字段内容 |
| --- | --- |
| 来源 | episode_id、source=teacher/policy、代码/资产/配置版本、训练 seed、场景 seed、case、安装版本、动作 schema |
| 时间 | physics_dt、policy_dt、physics_step、policy_step、仿真时间；图像另有采集/接收时间与有效 mask |
| 状态 | 执行前/后完整物理状态、可观测量、控制历史、门/对象状态、模型参数上下文 |
| 动作 | raw/clipped/physical target、实际 ctrl、实际执行器力；额外噪声施加位置与种子 |
| 目标 | reference_id、参考时间/帧、任务方向、目标角；语言和图像暂缺时保持未提供 |
| 结果 | terminated、truncated、success、failure_reason、阶段/物理事件、有效步 mask |
| 模型检查 | 需要时保存同一起点的真实与预测 rollout、各状态块误差、动作梯度诊断 |

终止前最后状态必须保存。环境自动 reset 后的新初态不能被当成上一回合的 next_state。训练 RSI 可从参考中途开始，但需同时恢复机器人、门、速度和历史/动作上下文；reset 后接触求解缓存的重建与稳定步骤须标明。**完整任务评测永远从规定任务初态开始**。

采样策略：每个 50 Hz 策略步保存完整 transition；每个 500 Hz 物理步计算越界、非预期接触、饱和与失稳等审计量。数据采集时保存足够物理子步命令/状态，以判断降采样造成的接触丢失；报告可用较低频曲线，但不把 25 Hz 净空最小值写成连续时间最小值。

## 7. 数据划分与评测隔离

分开记录三种划分：

1. WM 监督训练/验证按完整真实交互 episode 分组，禁止相邻帧或同一 episode 的切片泄漏；需要检验参数外推时再按场景组合分组。
2. 参考库单独记录 reference_id 及已见/未见身份。B0 允许在固定已见参考下评估新初态/物理条件；未见参考泛化属于额外评测，不是当前隐含门槛。
3. 完整任务的 held-out 由冻结条件清单及其是否参与参数选择定义。当前 P6 C01–C20 已参与开发，属于回归条件，不能再叫完全未见测试。

同一参考可以产生不同物理 episode，但这些身份必须可追溯。不能把一条参考或交互轨迹的切片分别放入 train/test 后宣称新的独立任务或参考泛化。

B0-03/04 的诊断片段与 B0-05 的从头任务分表报告。B0-06 新建冻结的 held-out 条件清单；不为每一个测试扰动现场调用教师生成最优参考。给定的参考类型、选择规则、初始对齐规则和 Actor 输入都在评测前固定。

WM 检查至少分别报告：自由运动、首次接触、稳定抓持、滑动/丢失、松爪；1、7 和 32 个策略转移步的状态误差。O1 的 `horizon=8` 在所选 WM learner 中是 8 个存储状态、7 个被评分转移，不写成已经有 8 步监督。

模型误差必须用真实物理片段比较，同时观察一步策略更新/连续训练对真实任务的作用。动作梯度存在且为有限数，只能说明计算图接通；不能单独证明模型梯度正确。接触切换附近的有限差分只作局部诊断，不当成全局光滑性证明。

## 8. 保存与恢复

轻量代码、来源锁、实际配置、episode 索引、逐案 JSON/CSV、曲线与必要视频提交 GitHub。大 replay、完整原始数组和权重保存到训练输出目录并记录准确路径，不制作本机压缩归档，不把数据/环境/第三方源码大包提交 Git。

至少保存 actor、critic、WM、normalizer、解析配置和真实计数。若未保存 optimizer/replay/sampler/RNG，明确称“权重检查点”；如需续训则补最小完整状态保存，并准确区分 warm start 与完整 resume，不另建通用恢复框架。
