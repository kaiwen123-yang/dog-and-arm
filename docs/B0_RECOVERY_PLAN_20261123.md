1. 先复用已记录的 native held-target 在 CPU3.16/Warp 3.16 几乎同一步失败的事实，挑一条预抓取和一条稳定推拉窗口做最小对照。三环境共用同一模型源、初态、真实前缀、物理目标序列和 2 ms 时间轴。
2. 核对编译后的质量/惯性、执行器增益与偏置、夹爪约束、接触对、solver/integrator/tolerance、warmstart 与同步方式；找首次状态/接触/力的实质分歧。只修能解释该分歧的一项，不以大范围改物理参数使轨迹碰巧接近。
3. CPU3.16 与 Warp 的一致差异优先排查共用版本/接口；两者不一致再看 GPU 专项。`MULTICCD` 警告本身不作因果证明。
4. 动作回放用于定位。最终迁移必须让同一冻结 Actor 在各后端自己的实时状态上闭环产生动作；共用同一参考协议和阈值。先两侧 nominal，失败就记失败/未展开 C，不把未测写成 0/20。
5. 若短期只能做到后端专用包，保留并准确报告该限制。不能拿一套 native 最佳包和另一套 Warp 最佳包宣布同包可迁移，也不因此自动启动后续多模态阶段。
