## 4. 执行顺序

### A. 核实现场，建立一条主配方

先检查工作树、main、现场进程、`.local-pair/*.exit`、各 run 的 `outcome.json` 与恢复文件。历史现场为 AutoDL `/root/autodl-tmp/dog-and-arm-b0-pair-v1`，本次未重新登录确认其现状。旧队列已回收，不按旧 tmux 描述重开。

读取最新 [训练清单](../results/b0/standard_baseline_20261124/contact_training.json)，保存继承与新增成本。以 `config/b0/pair_effort_aligned_grip_fixed_stats_lane_age.yaml` 为已实现机制清单的起点，解析出唯一新主配方；不能仅修改 YAML 名称就宣称行为生效。

标准 Actor 起点保持 `results/b0/free_s0_cloud_servo_r2/checkpoint_001000.pt`；WM 从 `results/b0/contact_s0_wm_held_r2/wm_002000.pt` 接续明确登记的接触预热。Actor/normalizer、Critic、WM、各优化器、RNG、采样器与 replay 的初始化或恢复分别记录。不得加载混合策略 Actor 作为标准起点。

### B. 对齐采集生命周期，保留接触前缀和回合边界

固定 [mjlab 环境](https://github.com/HybridRobotics/mjlab_research/blob/dd51a9fcc98791a2f0b018b3c7f71a3eefd5ecdd/src/mjlab/envs/manager_based_rl_env.py)在每个环境步后复位 terminated/time-out 的 env IDs，其他环境继续；固定 [runner](https://github.com/HybridRobotics/supermimic/blob/abc124c1bd5976341034668af3d12c087f2f1f55/src/supermimic/runners/supermimic_runner.py)持续保存 pre-step 状态和动作。当前 `ContactRun.collect` 在同步 40 步 cohort 中首次 terminal 后停止该 lane 入库，下一 cohort 才重置。接触短 episode 常只贡献一行，自由运动可贡献多行。这是已证流程差异，性能因果仍待实测。

本轮先利用已有 `ContactPlant.reset(..., ids)` 实现选定 lane 终止后的新 episode 采集。接触初态仍须运行登记的真实 200 ms 前缀；各 lane 独立维护前缀/策略模式、motion/reference clock、episode ID、history、上一 clipped 命令、物理计数和 sampler 边界。重启后不能继续旧 episode 的历史，也不能为了某 lane 的前缀而暗改其他 lane 的物理时钟。

配套处理：

1. replay 的 H7 必须在同一 episode 内连续，不能只用七行 `valid=True`，把 reset 前后拼成一个动力学窗口。数值有效的 terminal 后继可作为原回合末端，跨回合后继不合法。
2. 教师前缀、策略有效转移、终止后的诊断积分和等待分别计数。Ratio 只由原定义的新增有效策略转移驱动，前缀不冒充策略经验或回报。
3. ReturnSampler 保持实际首失效时刻的状态、参考和 dt 评分；已修复的首失效计分不得退回完整 20 ms 冒领奖励。完整正式评测仍首失效停止、余段零回报。
4. 保存全采集的紧凑 episode/phase/首失效/峰力/双指载荷统计，并在少量代表 cohort 保留完整子步数据。不中断 episode 的恢复须保存可继续的物理状态（qpos/qvel 及后端所需 act/solver warm-start）、接触累计计数、各 RNG、新增 lane 生命周期、history、时钟和采样器/Ratio 缓冲；否则明确行政截断、恢复后重新运行真实前缀，并标为边界恢复。普通 40 步记录块结束不是物理 terminal，不能静默丢失或拼接半个回合。
5. 用相同冻结 Actor、相同参考资格与预登记种子，对旧 cohort 和新生命周期做一个小规模采集对照。核对总物理步、前缀成本、有效数据率、每相位 H1/H7、独立 episode 和真实持续双指；需要因果学习比较时，最多保留一条同初始化的短预算控制，不扩展为八路搜索。

**不要预设重构 Actor 初态池。** 当前训练在物理门槛失败后仍积分十个子步，`valid_full_interval` 检查数值/容量；首次失败的完整区间已进入 H1/Actor，之后 lane 才退出。Actor 不要求未来 H7/H32 存活。逐 lane 重启能增加机会，不能保证每次握持更久，也不能凭空制造 H7 接触长窗。

### C. 补齐真实接触覆盖，用原损失预热 WM

此项数据盘点可与 B 的实现并行，合入训练时按依赖顺序进行。现有数据已补过 512 lanes 的握持 H7 窗，不能重复同一批配比后宣布覆盖问题已解决。

先按两侧及接近、建立握持、保持握持、小角度推拉、保持、释放/撤离列出库存：训练/验证身份、独立 episode/lane、参考 phase、实际指载荷、力和动作跨度、完整 H1/H7，以及用于诊断的 H32 窗。参考处于 open 不等于真有双指接触。登记 eligible 起点及前缀/尾部约束造成的排除数；没有证据不改变 RSI 范围或任务时间。

只补缺失的**训练身份**。来源可为已有登记训练教师、历史成功控制包的真实交互或当前标准策略；分别记录来源和成本，验证与 H 均不入训练。动作必须经原伺服真实固定执行完整 20 ms，不能把 500 Hz 变化命令抽样后当成恒动作转移，不能把 2 ms 扩成 20 ms。可以在训练状态上用已登记幅度做真实小扰动补动作响应，保留失败及所有尝试，不筛掉失败只留下好看的片段。

预热保持原 `ContactRepresentation`、WorldModelLearner、H1/H7 及现有 2/8 minibatch 组织；Actor/Critic 不更新，不使用 `--tcp-loss`、`--train-h32` 或新梯度损失。建议先预登记新增 WM minibatch 0/200/1000 检查点，按模式误差决定是否继续；这些是检查节点，不是强制墙钟终止或成功承诺。补采与预热均计入新增训练预算。

复用 `fit_contact_model.py` 的原学习逻辑，但注意其当前 `--resume-wm` 要求相同数据清单。新训练数据上的初始化应明确实现“加载门 WM 权重、登记新数据和统计/优化器处理”的最小入口，不篡改旧 metadata 冒充原 run 续训。第一候选保留 held_r2 统计以便诊断；若有实证需要用新训练统计，单列处理与受影响函数/优化器状态，不同时混改多个配方。原脚本硬编码的 `actual_physics='native held teacher'` 与 `teacher_samples` 也须随新入口改为真实 backend/行为来源及分母，不能把 Warp 或当前策略数据记为 native 教师。

验证继续使用已冻结的同窗集，并补新采集种子的独立轨迹；不把已有验证挪进 optimizer/replay/normalizer。比较 H1/H7/H32 的状态 loss、TCP/门角/夹口与自由运动退化，保留 held_r2、保持和常速参照。下一次联合学习至少应选到两侧接触相对初始化有可解释改善、其他关键模式没有明显崩坏的 WM；若预热未改善，检查缺失模式/数据映射并继续有据补采，不能只凭总体 loss 下跌授予通过，也不无限追求一个离线指标而不做物理学习。

已有 native H7 导数只有两状态、两动作、单一幅度。确需判断 WM 动作响应时，在主 Warp 后端选少量匹配状态，以两档扰动区分可辨识变化和接触非光滑性；它是旁路诊断，不成为新训练损失。原 encoder 诊断未证明全面饱和，保留核心网络。

### D. 实际联合训练，依据真实进展持续推进

从同一个标准 Actor 与选定预热 WM 建立新运行，Actor 起点继续来自当前策略在线 replay。主线保留固定 effort、ReturnSampler、Ratio、clip-last、lane/age 和 B 中已核验的采集生命周期。联合训练继续更新 WM 权重；Actor 反传时冻结 WM 参数并保留导数。normalizer 策略与预热出口一致，写入实际配置。

预登记 u0/1/10/50，之后 u100/200 及有意义的后续节点。u0、u10、u50 及扩展节点保存同一冻结 checkpoint 的正式十项成绩；u1可先做少量受影响入口诊断。正式入口仍是：

```bash
bash scripts/b0/evaluate_standard_contact.sh <新训练run> <冻结更新数> warp
```

`train_contact.py --config ... --run ... --updates ...` 继续作为联合训练入口；新主配方及生命周期尚未实现，执行者先保存真实配置和实现，再写实跑命令。本计划不把未存在的 YAML 或新参数冒充已可运行。

每个节点同时看：两侧各片段首次失败时刻、持续双指时间/实际载荷、首臂命令和夹口跳变、门力/TCP/把手误差、已登记阶段事件，以及独立 WM 误差和真实覆盖。低门力但夹口张开不算改善；一个 release 成功不替代十项或完整任务；十片段均值不当完整双侧回报。

有真实双侧持续接触、阶段或稳定控制进展时继续采集和训练，不能因为某个短节点仍 0/10 就自动终止。若两个有意义的扩展节点仍反复首失效、阶段无新增或退化，暂停同配方加预算，定位具体数据/接口问题后再继续；这不是宣布标准阶段结束，也不是切换新算法的许可。不要只因 u200/u500/u1000 这些数字就强制停止或盲目延长。
